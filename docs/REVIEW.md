**Дата снимка:** 6 сентября 2026  
**Статус:** канон плана на этот этап. Канвасы не источник правды. Стратегия: `.cursor/rules/huntos-strategy.mdc`. Хроника решений: `finance/CHRONICLE.md`. Финмодель заморожена.

# 1. Диагноз: почему это ощущается как пиздец

HuntOS по канону владельца — **CRM соискателя + якорь-резюме + инжест вакансий + AI по кнопке**. North Star — **WAS**: человек сдвинул карточку за 7 дней. Activation — резюме в профиле **или** ≥3 карточки за неделю.

То, во что проект фактически упарывается — **ферма парсеров чужих HTML**. Это другой продукт: агрегатор вакансий с бесконечным хвостом сайтов. У него другие юнит-экономика, другой ops и другая вероятность сломаться завтра утром, когда HH / Яндекс / Т-Банк поменяют разметку.

Узкое горлышко здесь не «мало досок», а:

1. **Каждая новая доска** = хрупкий селектор + антибот + свой URL-канон + тесты на фикстурах, которые гниют. `backend/app/services/scraper/sources/career.py` один уже **>2200 строк**. Каталог карьерных сайтов — порядка **двадцати компаний**, у каждой свои IT-фильтры в `career_catalog.py`.
2. **Скрейп HH с VPS** прямо противоречит здравому смыслу (баны IP) и тому, что владелец писал в master-контексте: инжест — из браузера юзера. При этом в воркере крутится `HhSource` с `default_max_pages=40`.
3. **Фон LLM после каждого кроула.** После drain очереди скрейпа для каждого задетого `user_id` вызывается `score_pending(..., limit=15)`. После разбора TG — ещё `limit=8` **на каждого пользователя в базе**. Это не N×M «все вакансии × все юзеры заранее», но это **фоновый LLM без клика**. На 100 юзерах с полным inbox это уже жрёт ключ и время воркера. Канон: LLM только on-demand.
4. **Activation не требует 20 карьерных сайтов.** Нужны: залил PDF → видишь нормальное резюме → в inbox сразу 3 карточки → двигаешь их. Карточки могут прийти из клиппера, TG-ссылки или уже существующего donor cache. Ещё один парсер Avito/МТС это не ускоряет.

Отдельно: в серии правок 5 сентября 2026 агент **действительно писал заметный говнокод** — не «чуть неаккуратно», а ломал соседние куски по пути (см. раздел 4). Это справедливо бесит: даже правильная фича, сделанная в режиме «быстрее закрыть дыру», оставляет швы, которые потом страшно трогать.

# 2. Канон, от которого план не имеет права отъезжать

Источник правды: `.cursor/rules/huntos-strategy.mdc` + `finance/CHRONICLE.md`. Канвасы — нет. Финмодель **заморожена** 5 Sep 2026 — цифры не крутим.

**Продукт:** Career OS = резюме-JSON + воронка + инжест. Не коучи, не социалка, не маркетплейс.

**Кто платит:** IT Middle/Senior / релокант, активный поиск, ЗП ≳150k, болит ATS и хаос воронки.

**Что продаём:** ATS-bypass / буллеты / follow-up / negotiator. Не простыни cover letter. HH-письмо — исключение-workaround (форма HH, резюме на HH не трогаем).

**Деньги:** Free / Lite 490 / **Plus 990** (касса первых месяцев) / Pro 1990 якорь / Lifetime ~2990 на 3 мес. ЮKassa **после** ядра. AI полный — на платных; free — CRM + клиппер + крошечный taste. До пейволла AI в коде **не гейтить**.

**Не делать без отдельного «да»:** auto-apply, продажа intent, B2B «перехват оффера». Публичные агрегаты anti-ghosting — позже, когда WAS ≳500.

**Архитектура:** модульный монолит FastAPI. Тяжёлое (скрейп, LLM) — не в HTTP. Не тащить Kafka/Celery/ES. Мэтч на масштабе — фичи + локальный скор, не LLM N×M.

Ближайший порядок в правиле (это и есть очередь внедрения, не «ещё парсер»):

1. Zero-Data onboarding (PDF → профиль + 3 карточки) + изоляция тенантов
2. Редактор ATS (JSON + PDF) + буллеты под вакансию
3. Chrome-клиппер + TG-бот (ссылка → карточка)
4. ЮKassa + гейты на AI
5. Дешёвый LLM + лимиты + referral + BIP
6. Anti-ghosting / negotiator после данных на досках

# 3. Что уже сделано за весь проект (инвентарь по слоям)

Снимок репозитория на 6 сентября 2026, включая незакоммиченное и то, что накопилось до ревью. «Сделано» ≠ «готово продавать». Где дыра — написано прямо.

## 3.1. Инфраструктура и запуск

Есть **не игрушечный** контур под соло-VPS:

- Docker Compose с профилями `data` / `app` / `edge` / `obs`: Postgres 16, pgbouncer, Redis, backend, **отдельный worker**, frontend, nginx 80/443.
- Харденинг: read-only контейнеры, drop caps, secrets через файлы (`infra/compose/gen-secrets.sh`).
- Edge: nginx, Cloudflare real-ip, origin-pull сниппеты.
- Observability: Prometheus, Loki/Promtail, Grafana, Jaeger, Alertmanager, ntfy. OpenTelemetry в API. Health/ready разделены (`/api/health` не трогает БД, `/api/ready` проверяет).
- Bootstrap VPS: пакеты, sysctl, WireGuard, SSH, nftables, audit, CrowdSec, unattended upgrades, Falco-правила, бэкапы и restore-drill.
- CI в истории коммитов: App CI, Trivy report-only, GHCR, Dependabot caps.

Это **дорого по вниманию** относительно стадии «0 юзеров», но это не парсеры: это то, без чего соло не хочет ловить проде в 3 ночи. Трогать не надо, пока не деплоим кассу.

**Нет:** биллинга, тарифов в `User`, ЮKassa, feature flags на AI.

## 3.2. Аккаунты, сессии, изоляция

- Регистрация / логин по email+пароль, cookie `hunt_session`, заголовок `X-Hunt-Session` для расширения.
- Google OAuth как вход (`google_sub`) и как календарь (отдельный контур токенов в профиле).
- Первый юзер — host. Host может смотреть чужой кабинет через `X-Hunt-As`. Обычный юзер этот заголовок **не** эскалирует.
- Тесты `backend/tests/test_isolation.py`: вакансии гостя не светятся в inbox хоста; as-user работает только у host.
- Профиль (`UserProfile`): резюме текст/файл/JSON, ключ LLM (запечатан), настройки календаря, кастомные поля, exclude компаний и т.д.
- **Нет полей тарифа, лимитов AI, referral-кода, share-slug.** Публичное резюме на момент снимка завязано на числовой `user_id` — дыра приватности (перебор id).

Чат: гости пишут хосту, не друг другу. Модели Conversation / Member / Message есть, UI — `chat-panel`. Это не социалка и не ICP-фича; жить может, развивать не надо.

## 3.3. Ядро CRM (то, за что человеку вообще заходить)

Это самая ценная уже написанная часть.

**Модель вакансии** — жирная, но осмысленная для воронки: source/source_id/url, роль, компания, ИНН, иконка, грейд, формат, гео, зарплата min/max/raw, описание/требования/задачи/условия, skills/tags/stack_ids, raw_payload, стадии пайплайна:

`inbox → to_apply → waiting → screening → interview → offer → rejected` + `trash`.

Плюс: match_score и rationale, adaptation_advice, cover_letter, notes, контакты (tg/email/phone), fingerprint и extra_sources (склейка дублей с нескольких досок), custom_values и card_fields на карточке, duplicate_of, last_touch, stage_entered, outreach/ping, hh_pulse (пригласили/отклонили с HH), next_step + kind, google_event_id.

Дедуп: уникальность `(user_id, source, source_id)` + fingerprint.

**Inbox** (`/`): лента, фильтры (формат/грейд/источник/стек), поиск, клип URL, открытие карточки. Это рабочая поверхность WAS.

**Воронка** (`/pipeline`): канбан со стадиями, drag-and-drop, reorder API, bulk stage.

**Карточка (drawer)** — перегруженный «бог-компонент» (~1100 строк): сделка / HR / ещё, описание, кастомные поля, шаги (скрининг/собес/тестовое/оффер-дедлайн), коллизии календаря, HH pulse, пинг «написал», буллеты под вакансию, ссылки, контакты. Это и сила продукта, и магнит говнокода: любое «ещё одну кнопку» сюда же.

**Направления (hunts / thesis):** несколько поисков у одного человека, пин карточки к hunt, поля на hunt vs на карточке, HuntSwitcher. Имеет смысл для ICP «я смотрю backend и отдельно ML».

**Время** (`/time`): сетка собесов/дедлайнов, слоты пинга, nudge queue «эйчар молчит N дней».

**Контакты:** вытаскивание HR с карточек, доска контактов.

**Кастомные поля:** чекбоксы/даты/числа на карточке направления — CRM-гибкость, не поиск.

Это уже **продаваемый Free-слой**, если инжест и резюме не стыдно показать.

## 3.4. Резюме как якорь (Phase 1, частично)

Сделано и это уже правильный продукт:

- Жёсткая JSON-схема: name, headline, contacts, links, summary, about_items, skills / skill_groups, experience (буллеты с children), education, languages, courses, hackathons.
- Нормализация на бэке (`normalize_resume`, `flatten_resume`) и дубль логики на фронте (`frontend/lib/resume.ts`) — **два источника правды**, это технический долг.
- Двухпанельный редактор `/resume`: слева поля, справа ATS/LaTeX-лист (`ResumeSheet` + CSS печати A4). PDF = `window.print()`, не `@react-pdf/renderer`. В `package.json` фронта только Next 16 + React 19 + Tailwind 4 + lucide. **Нет shadcn, нет react-pdf.**
- Загрузка PDF/TXT: `pypdf` → текст. LLM-разбор в JSON on-demand при аплоаде; нет ключа — эвристика «первая строка = имя, остальное в summary».
- Onboarding-шит: если нет резюме и мало карточек — «положи PDF». После аплоада `POST /onboarding/seed` кладёт до 3 вакансий из **donor cache** по пересечению стека. Если пул пустой — честный текст «карточек нет, вставь ссылку».
- Буллеты под вакансию: `POST /adapt` больше не простыня советов. LLM возвращает experience, `merge_adapted_experience` матчит по компании, **не создаёт выдуманные места работы**, хранит `previous_experience` на карточке. «Вписать в резюме» пишет в `profile.resume_json` (мастер-CV, не копия на вакансию как отдельная сущность).
- Публичная страница `/p/{user_id}?target={vacancy_id}` без шелла логина: чужой видит лист; если на карточке есть adapted experience — подмешивает. **Нет opt-in, нет непрозрачного токена, нет robots/noindex, id перебирается.**

Миграция `0016_resume_json.py` — колонка JSON на профиле.

**Не сделано до «можно стыдно не быть»:** Word-аплоад, единый нормализатор JSON, клиентский react-pdf если печать в Chrome врёт ATS, версионирование резюме per-job (сейчас вписать в мастер затирает предыдущую адаптацию), пейволл.

## 3.5. Инжест: три трубы, из которых две правильные

### А. Chrome-клиппер (правильное горлышко инжеста)

Расширение MV3: popup, options (origin HuntOS), cookie `hunt_session`, `POST /api/vacancies/clip` с url/title/html.

Умеет: отличить карточку от каталога и от мусора (локальный judge + серверный `clip_page.judge_page`), force «всё равно положить», понять HH apply URL `vacancyId=`, переписать на `https://hh.ru/vacancy/{id}`.

Слой письма: content script на hh.ru + service worker. Кнопка «письмо HuntOS» → clip → `POST /hh-letter` → нативная вставка в textarea Magritte (не submit). Если поля нет — clipboard. Письмо короткое, 3 буллета, ссылка на `/p/...`.

Это **совпадает с каноном** (инжест из браузера юзера). Качество кода расширения среднее: дубль fill-логики в `hh.js` и `popup.js`, селекторы HH сгниют, origin по умолчанию `127.0.0.1:8443`.

### Б. Telegram-бот (правильное горлышко)

Отдельный Bot API на юзера, bind через `/start` + token, не общий Telethon-чат на всех.

Умеет: ссылка в сообщении → `clip_vacancy` → карточка. Дайджесты, тихие часы, пинги по слотам, апдейты стажировок/хакатонов. Это killer-ingest №2 и его надо **довести до «кинь ссылку — карточка есть»**, не обрастать парсерами каналов.

### В. Host Telethon + каналы (серая зона)

Пул каналов, парсинг постов в `TelegramPost`, LLM/правила достают вакансию, кладут в кэш/карточки. Разбор **один раз в общий кэш** — это правильно по канону. Но это снова парсер + LLM в фоне + зависимость от сессии Telegram хоста. Для запуска 100 signup это не блокер и не якорь PLG.

## 3.6. Скрейп-ферма (основной перекос внимания)

# 4. Что сделали 5 сентября 2026 в чате — и почему это выглядит как говнокод

Коротко по фактам, без оправданий «мы же быстро».

**Сделали по смыслу правильно (направление канона):**

1. LLM-parse PDF в JSON при аплоаде, fallback без ключа.
2. Adapt → реальные буллеты в JSON, не советы; мердж без выдуманных работодателей; «вписать в резюме».
3. HH: письмо в форму по клику, без auto-apply; публичный лист чтобы ссылка не 404.

**Как сделали — плохо:**

- Режим «самая простая дыра» без стоп-крана на парсерах: после буллетов сразу HH DOM + публичный CV, не «зафиксировать качество резюме-редактора».
- `vacancy-drawer` ещё раз раздут: IIFE, потом вынос, старые `suggestions` живут рядом с новым `experience`.
- Дублирование схемы резюме Python ↔ TypeScript.
- Промпты внезапно на английском в русскоязычном продукте (`ADAPT_*`, `HH_LETTER_*`, `PARSE_*`).
- Публичный CV по integer id без согласия — для PLG ок идея, для доверия ICP дыра.
- Расширение: копипаста fill textarea, хрупкие `data-qa`.
- Регрессии по дороге, которые агент сам создавал: стёр `function pageShape` в popup, выкинул импорт `onboarding_router` из `main.py` (тесты упали NameError), сломал `jdOpen` state в drawer, мёрдж сначала писал «Invented Corp» во второй job пока тест не поймал.
- В `vacancies.py` висит unused import (ruff F401) — шум в и без того толстом роутере.
- LLM parse/adapt/hh-letter **в HTTP-запросе**, хотя архитектурное правило — не блокировать API тяжёлым. Для соло с 1 юзером живёт; как образец «как писать дальше» — плохой.
- Master-контекст требовал `@react-pdf/renderer` и shadcn — сознательно не тащили (правильно не тащить ради галочки), но и не зафиксировали решение письменно, поэтому ощущение «делаем не то ТЗ».

Итог: фичи бьют в канон, **исполнение — черновик в проде**. На стадии соло это переживается, если не плодить ещё слой. Если плодить — владелец прав, что огорчается.

# 5. Что мы больше не внедряем (стоп-лист)

Пока владелец не скажет иначе, **запрет на работу**:

1. Новые карьерные сайты, новые kind в `career.py`, новые доски в registry.
2. Любой новый HTML-парсер «чтобы inbox был богаче».
3. Починка/расширение HH-скрейпа с VPS (селекторы, headed chrome, обход антибота). Клиппер — да; серверный HH crawl — заморозка.
4. Auto-apply, автоклик «Откликнуться», заполнение Greenhouse/Lever/Huntflow с сабмитом.
5. Простыни cover letter в UI. HH-письмо уже есть — не размножать.
6. Coach Studio, поиск людей, социалка.
7. B2B intent/offer-radar, персональные токсик-бейджи компании.
8. ЮKassa / пейволл / тарифы в User — **пока** резюме+клиппер+буллеты не стыдно показать живому ICP (канон: касса после ядра).
9. react-pdf, shadcn, Kafka, Celery, ES — не ради галочки из вставленного master-context.
10. Финмодель.
11. Ещё стажировки/хакатоны/зарплатные источники.
12. Фоновый `score_pending` расширять. Наоборот — выключить или заменить локальным скором.

Ломающийся парсер в проде чиним **минимальным патчем или выключаем доску**, не «переписываем адаптер».

# 6. План внедрения: куда, почему, какие шаги

Это не «ещё фичи». Это **сужение** к тому, что даёт signup → activated → WAS → готовность взять 990.

Каждый блок: цель, где в коде, шаги, критерий «готово», что не входит.

## Этап 0. Стоп и зачистка (сначала, иначе план враньё)

**Зачем:** сейчас нельзя честно строить дальше на дырявом публичном id, двойном JSON, фоновом LLM и 1100-строчном drawer.

**Куда:** точечно существующие файлы, без новых доменов.

**Шаги:**

1. Зафиксировать freeze скрейпа в правиле агента (одно предложение: не добавлять sources).
2. Выключить или сильно урезать фоновый scoring: `scheduler._scrape_tick` / `_telegram_job` не зовут `score_pending`. Fit — по кнопке на карточке (уже есть `POST /score`). Inbox может жить без процента.
3. Публичный CV: непрозрачный `share_id` на профиле, default **выкл**, включение в редакторе резюме. Старые `/p/{user_id}` либо редирект, либо 404.
4. Один модуль нормализации резюме: либо TS вызывает те же правила, либо фронт доверяет ответу API и не расходится.
5. Промпты — один язык (русский, как scoring Fit).
6. Drawer: буллеты не раздувать дальше; HH-письмо не тащить в drawer вторым UI.
7. Расширение: одна функция fill, без копипасты popup/hh.js.
8. Прогнать существующие тесты, починить только то, что сломали мы (onboarding import, merge, public). Не писать новые парсер-фикстуры.

**Готово когда:** публичный лист не перебирается, скрейп не жжёт LLM, резюме не двоится, тесты зелёные, в git нет «случайных» NameError-класса дыр.

**Не входит:** рефакторинг всего `career.py`.

## Этап 1. Zero-Data, который реально хукает (activation)

**Зачем:** 15% activation в модели. Магия: уродский PDF → нормальный ATS-лист + 3 карточки. Сейчас: без ключа LLM всё свалено в summary; без donor cache карточек нет; Word нет.

**Куда:** `settings.upload_resume`, `services/resume.py`, `onboarding.py`, `onboarding-sheet.tsx`, `resume-editor.tsx`.

**Шаги:**

1. Онбординг всегда заканчивается **видимым** листом, даже если LLM упал: не оставлять человека с пустыми полями без объяснения.
2. Если donor cache пуст — не притворяться поиском: CTA «вставь ссылку HH» / «поставь клиппер» / «кинь ссылку боту». Три карточки из пустого пула не обещать.
3. Seed только из кэша, **без** живого скрейпа в HTTP.
4. (Опционально, маленький) `.docx` через python-docx — много ICP приходят с Word. Не трогать сложные doc.
5. После сида сразу inbox, не «настройки поисков».
6. Проверка изоляции: seed юзера A не кладёт карточки юзера B (уже должно, проверить тестом).

**Готово когда:** владелец заливает свой PDF на чистый аккаунт и за 30 секунд видит поля + либо 3 карточки, либо честный следующий шаг инжеста. Без ключа LLM — не идеально, но не пустой экран.

**Почему не парсеры:** 3 карточки из общего кэша или из одной ссылки активируют. Двадцать карьерных сайтов — нет.

## Этап 2. Резюме как PLG-якорь (то, что показывают на Habr)

**Зачем:** бесплатный PDF + JSON — повод зарегистрироваться. AI-адаптация потом = Plus.

**Куда:** `/resume`, `ResumeSheet`, печать, публичная ссылка после этапа 0.

**Шаги:**

1. Довести лист до «можно слать senior-рекрутеру»: одна колонка, нормальная типографика, без выпадения полей.
2. Печать: проверить реальный Save as PDF в Chrome (ATS). Если print CSS врёт — тогда уже `@react-pdf/renderer`, не раньше. Не ставить библиотеку «потому что в промпте написано».
3. Сохранение без потери буллетов/вложенности.
4. Публичная ссылка: тумблер «открыть для ссылки из письма HH». Баннер «HuntOS» без B2B talent pool.
5. «Вписать в резюме» не убивает мастер молча: либо копия per vacancy (`adapted_resume_json` на карточке), либо явное «это станет основным». Продуктово правильнее **копия на карточке** + кнопка «сделать основным».
6. Не строить конструктор шаблонов. Один Harvard/LaTeX.

**Готово когда:** `/resume` на живом CV не стыдно. Публичная ссылка работает только если включил.

## Этап 3. Инжест, который кормит CRM (клиппер + бот), не ферма досок

**Зачем:** канон прямо говорит — клиппер и TG-ссылка ранние киллеры. Юзер уже сидит на HH. Мы не должны зеркалить HH на VPS.

**Куда:** `extension/*`, `clipper.py`, `telegram_bot.py`. Скрейп registry — только читать/чинить падения.

**Шаги:**

1. Клиппер: одна кнопка «в inbox» со страницы вакансии (HH, Habr, HireHi, карьерка, Greenhouse-страница как HTML). Judge мусора оставить — это защита inbox, не парсер досок.
2. Не вкладываться в новые `data-qa` HH дальше текущего письма, пока 10 живых откликов не покажут, что поле не находится.
3. TG-бот: кинул ссылку → карточка с title/company/url. Если html не достать — карточка всё равно есть, описание доберёт клиппер позже.
4. Donor cache **использовать** для онбординга и дедупа, не растить.
5. Поиски в settings: не добавлять фильтры. Если HH-кроул с VPS падает — выключить source `hh` в UI, оставить клиппер.
6. Документировать юзеру в одной строке: «вакансии в HuntOS попадают из клиппера, бота и включённых поисков; поиски — опция, не ядро».

**Готово когда:** путь «нашёл вакансию на HH → клип → карточка в inbox → сдвиг в to_apply» без настроек скрейпа. Бот — тот же путь ссылкой.

**Серверный скрейп после этого:** legacy, который можно кормить кэш, пока живёт. Не roadmap.

## Этап 4. Буллеты как платный смысл (ещё без кассы)

**Зачем:** продаём ATS-bypass. Сейчас цепочка есть, но рваная: подобрать → смотреть в drawer → вписать в мастер → PDF на другой странице не живой.

**Куда:** `adapt_resume`, drawer, `/resume` с контекстом `?vacancy=`.

**Шаги:**

1. Адаптация пишет в JSON карточки, мастер не трогает, пока не сказал.
2. С карточки «открыть лист под эту вакансию» — тот же ResumeSheet с merged experience.
3. Не выдумывать навыки списком skills, только переформулировка существующих буллетов (уже почти так).
4. Счётчик вызовов в профиле (`ai_adapt_count`) — задел под лимит free=3, **без** пейволла UI.
5. Fit-скор: либо локальный (стек ∩ вакансия) сразу, либо по кнопке LLM. Не фон.

**Готово когда:** на одной вакансии подобрал буллеты, открыл лист, видишь keywords, мастер CV на `/resume` без query не изменился.

## Этап 5. Касса (только после 1–4 на живом себе)

**Куда:** новый домен `billing` в монолите: модели Subscription, webhook, `User.tier`, лимиты. Фронт: pricing + гейт на adapt/letter сверх taste.

**Готово когда:** тестовый платёж ЮKassa в тестовом магазине открывает 4-й adapt.

**Шаги:** не продукт-комбайн.

# 8. Критерий, что мы больше не «творим пиздец»

Можно снова писать фичи, когда одновременно:

1. Freeze скрейпа соблюдается неделю без «ещё одну компанию».
2. Фон LLM scoring выключен.
3. Онбординг на живом PDF даёт лист + понятный инжест.
4. Клиппер HH → карточка → буллеты → лист под вакансию — один счастливый путь.
5. Публичная ссылка opt-in.
6. Нет новых 200-строчных парсеров и нет новых 100-строчных вставок в drawer «заодно».

Пока этого нет, правильная работа агента — **этап 0–2**, а не «продолжаем дыры».
